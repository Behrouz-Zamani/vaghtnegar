# معماری وقت‌نگار

## سبک معماری
Clean Architecture با جهت وابستگی به سمت Domain:
- Domain مستقل از سایر لایه‌هاست.
- Application به Domain وابسته است و قراردادهای موردنیاز را تعریف می‌کند.
- Infrastructure پیاده‌سازی قراردادهای فنی و دسترسی به داده را بر عهده دارد.
- API ترکیب وابستگی‌ها و ورودی/خروجی HTTP را مدیریت می‌کند.

## ماژول‌های دامنه
1. هویت و دسترسی کاربران
2. مراکز درمانی و شعب
3. پزشکان و تخصص‌ها
4. بیماران و پرونده پایه
5. برنامه کاری و زمان‌های قابل رزرو
6. نوبت‌دهی، لغو و جابه‌جایی نوبت
7. پرداخت آنلاین و ثبت پرداخت حضوری
8. اعلان‌ها و یادآوری‌ها
9. گزارش‌ها و مدیریت

## قواعد کلیدی نوبت‌دهی
- زمان‌های قابل رزرو باید از برنامه کاری، تعطیلات، ظرفیت و استثناهای پزشک محاسبه شوند.
- جلوگیری از ثبت هم‌زمان دو نوبت برای یک ظرفیت باید در سطح پایگاه داده و منطق کاربردی تضمین شود.
- وضعیت نوبت و وضعیت پرداخت دو مفهوم مستقل هستند.
- تمام زمان‌ها در ذخیره‌سازی به‌صورت استاندارد و با منطقه زمانی مشخص مدیریت می‌شوند؛ نمایش تقویم شمسی در لایه ارائه انجام می‌شود.

## ملاحظات امنیتی
- رمز عبور به‌صورت متن ساده ذخیره نمی‌شود.
- اطلاعات اتصال و کلیدهای پرداخت وارد مخزن نمی‌شوند.
- دسترسی‌ها بر اساس نقش و محدوده مرکز درمانی کنترل می‌شوند.
- اطلاعات سلامت و هویت بیماران حداقل‌سازی و محافظت می‌شوند.

## تصمیم‌های باز
- نسخه دقیق .NET و سیاست پشتیبانی
- روش احراز هویت و مدیریت نشست/توکن
- درگاه‌های پرداخت هدف
- سیاست چندمرکزی و چندشعبه‌ای
- روش ارسال پیامک و اعلان
